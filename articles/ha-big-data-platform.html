Как построить отказоустойчивую Big Data-платформу без простоя

Где данные в реальном времени (транзакции, биллинг, телеметрия), простой кластера — прямые потери. «Дижитрек» (Диджи Трек, DigiTrack) рассчитан на работу без окна. Масштаб — в «Как масштабировать Big Data-инфраструктуру от одного кластера до федеративной архитектуры».

HA критичных сервисов

  • HDFS: Active/Standby NameNode + JournalNodes, авто failover.
  • YARN: ResourceManager HA.
  • Hive Metastore: PostgreSQL Patroni, проверка через VIP.
  • ZooKeeper: нечётный кворум, рестарт по одной машине.

Rolling restart

YARN NodeManager: drain → exclude, ждать numContainers=0, рестарт, RUNNING/healthy.

HDFS DataNode: dfs.exclude, IN_MAINTENANCE, рестарт, возврат в LiveNodes.

NameNode HA: сначала Standby, failover, затем бывший Active; кворум JournalNodes жив.

ZK + JN: по одной машине, проверка кворума после шага.

Patroni: reload без даунтайма или restart со switchover; VIP.

Hive Metastore: по инстансу, health-check БД через VIP.

JupyterHub: рестарт с проверкой до/после, минимальный impact.

Guardrails

Не больше N узлов сразу. Таймауты: зависание шага останавливает волну. restart_matrix по фактическим изменениям. Pre/post: REST NameNode/RM, JMX, VIP PostgreSQL, порты Hive.

SRE: JMX, VIP, ZK quorum, порты — состояние кластера видно онлайн. Пром: 40 узлов, 1 ПБ+, регулярный rolling restart без окна для бизнеса.
