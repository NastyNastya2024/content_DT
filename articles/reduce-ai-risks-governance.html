Как снизить AI-риски в банке с помощью Data Governance

AI-риск в банке — это не только «модель ошиблась». Это решение на данных без права, без качества, без мониторинга и без возможности объяснить, откуда взялся признак. Governance снижает этот риск системно, а не разовым аудитом.

Какие риски закрывает DG

Правовой: признак без основания. Качества: обучение на грязной витрине. Модельный: нестабильный вход. Операционный: нет владельца, некого чинить. Репутационный и регуляторный: нельзя восстановить цепочку решения.

Контроли: каталог признаков, правовые метки, DQ-гейт, lineage до решения, запрет на признаки вне каталога, мониторинг дрифта, разделение доступа, журнал версий. Для федеративных сценариев — отдельный класс партнёрских данных, которые не копируются в озеро.

Это та же статья-мост с хабом FL: без внутреннего governance нельзя обещать безопасное совместное обучение. Для CRO практический минимум — одна промышленная модель, полностью закрытая по этому списку, как шаблон для остальных.
